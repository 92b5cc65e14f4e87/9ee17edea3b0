# Endpoint Warehouse Simulator

This is the standalone Endpoint Warehouse Simulator. Its first module is inbound
receiving. Its deployable root is `web/`.
Read `README.md` and `docs/RECEIVING.md` before changing behavior. For native scene
work, also read `unity/OneShiftRackLab/README.md` and `WAREHOUSE_LIGHTING.md`.

Keep the immediate Home > Inbound > lesson path and lazy Unity loading. The user
plays in first person: real walking, bounded physical carton handling, and actual
barcode scans. A receiving action changes records and labels, never moves freight
automatically. The browser model is the one receipt authority; preserve exact
quantities, tracking values, duplicate rejection and physical placement checks.

Use fictional session-only data. Do not add company API connections, integrations,
analytics or persistent user data without a separate request. The Pages review
link is public. A noindex tag is not authentication.

Maintain large controls, plain task instructions, visible feedback and keyboard
access. Keep manual pause, browser activity and portrait gates independent. Clear
held inputs on inactivity. Use the existing charcoal, rust and cream palette and
local Segoe UI. No emojis or em dashes in copy or commits.

Use relative asset paths so the app works under a GitHub Pages project prefix.
Do not add personal-site links, legacy game launchers, a CNAME file or dependencies
on another website. Native namespaces and asset filenames remain OneShift for
compatibility; they are not a reason to restore the old browser modes.

Run `npm test` after receiving or host changes. Run `npm run test:browser` after
gameplay or integration changes. The native Chrome browser test is an authorized
repository verification workflow: use actual mouse, keyboard and DOM controls;
never inject scan codes, transform changes or stock records. Verify native report
passed flags, not only process exit codes. Native changes require validation,
versioned browser export and browser verification. Editor export path changes do
not change the already compiled player.

Keep the stable review URL. The workflow deploys only `web/` when `main` changes.
Preserve unrelated working changes and do not commit credentials or local caches.
